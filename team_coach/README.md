# Тренер Open Hyper AI

[Главная проекта](../README.ru.md) · [Игровой цикл](../docs/gameplay.ru.md) · [Справка по запуску](../offline_league/README.md)

Open Hyper AI исполняет действия героев, а отдельная постоянная сессия каждой команды принимает стратегические и тактические решения. В режиме `model` тренер получает свежую сводку каждые 15 игровых секунд или раньше после значимого события. История решений сохраняется в сессии на протяжении матча. У соперника отдельная инструкция на максимальное соревновательное давление.

[Карта команд, точек вмешательства и проверки изменений](INTEGRATION.md).

## Видимые тренеры в приложении

`Играть.cmd` запускает локальную лигу и связь с тренерами. Из [корневого README](../README.ru.md#промпт-для-двух-тренеров) можно одним промптом открыть или возобновить видимые чаты «Тренер Radiant» и «Тренер Dire». Оба продолжают ждать начало матча после подтверждения готовности.

По умолчанию обе стороны слушают игру в `observe`. Видимые тренеры выдают команды с интервалом из `model_cooldown_s` в `/status` или на значимое событие. Контроллер соперника между консультациями перепроверяет срыв по свежей телеметрии, меняет состав драки или выбирает доступный объект. Доступные действия проверяются по живому `/commands`. Журналы находятся в `%LOCALAPPDATA%\Dota Offline League\coach-events.jsonl` и `dire-coach-events.jsonl`.

Описанный ниже `--mode model` — отдельный вариант автоматического фонового управления. Он не заменяет просьбу пользователя запустить работающие чаты тренеров в приложении.

## Запуск на Windows

Для двух тренеров выбери сторону игрока через `--team`. Промпты для отдельных сессий и команда запуска находятся в [инструкции двухстороннего режима](INTEGRATION.md#два-тренера-и-коллы-игрока).

Для локальной лиги используй [запуск со сводками из журнала Dota и файловыми ответами](INTEGRATION.md#команды-тренера). Ручные команды доступны через `python -X utf8 -m team_coach.control list`.

Для обычного лобби с HTTP-обменом запусти сервер из корня проекта и установи адаптер в локальную папку скриптов Dota.

```powershell
python -m team_coach --install
```

В Dota создай лобби с сервером **Local Host**, включи заполнение свободных мест ботами и выбери **Local Dev Script** для **Radiant**. Для другой стороны выбери обычных ботов. Для тренировки Dire запусти сервер с `--install --team dire` и выбери **Local Dev Script** для Dire. Если Steam установлен в другом месте, команды принимают пути `--game` и `--workshop`.

Для следующих матчей с той же стороной и портом достаточно `python -m team_coach`. При смене стороны, порта или версии адаптера повтори запуск с `--install`. Установщик использует локальную копию Open Hyper AI из Workshop. При обновлении сохраняет предыдущую копию, которую установил сам.

## Во время матча

Для наблюдения за игрой Hyper AI используй `--mode shadow`, а для локальной лиги добавь `--dota-log ПУТЬ`. Этот режим пишет сводки и обнаруженные события в журнал, отклоняет ручные планы и обходится без вызовов модели. `python -X utf8 -m team_coach.watch ПУТЬ_К_ЖУРНАЛУ --follow` показывает состояние соединения и события по мере записи.

- `GET http://127.0.0.1:32125/status` показывает сводку команды, текущий план, число его пересмотров, подтвердивших его ботов и использованные токены. До первых Lua-пакетов сервер ждёт матч.
- Lua присылает состояние примерно каждые две игровые секунды. Сессия тренера консультирует команду каждые 15 игровых секунд, даже при неизменной карте. Потери героев, давление на вышки, угроза базе и тактические события вызывают раннюю консультацию; события объединяются с минимальным интервалом две секунды. Пауза останавливает периодический таймер. Параметр `--cooldown` меняет период сессии, а `--decision-interval` относится только к режиму правил.
- План привязан к матчу, героям и вышке. Lua вызывает штатные методы `GetPushDesire` и `GetDefendDesire` Open Hyper AI, и для выбранного плана может поднять оценку допустимого режима. Пуш исполняет штатный `PushThink`. За движение, отход и способности отвечают сами боты.
- В режиме `model` две сессии работают параллельно и напрямую задают пуш, защиту, фарм, Рошана, отход, удержание ульты и тактику драки. Ответ может содержать несколько согласованных приказов и отмены собственных приказов. Сервер проверяет свежесть, доступность целей и ботов; команды человека имеют приоритет. Правила не подменяют решения сессии во время запроса: действующие приказы и штатное управление героев продолжают работать. `--mode rules` включает отдельный вариант с автоматическими решениями по правилам.
- `GET /status` содержит `controller=session`, `coach_session` с ID постоянной сессии и текущего обращения, а также `last_model_result` с принятыми и отклонёнными приказами. Служебный файл `session-СТОРОНА/session.json` сохраняет идентификаторы. Новый матч получает новую историю; обрыв процесса восстанавливает текущую сессию. Таймаут ответа — 30 секунд, устаревшие тактические приказы отклоняются. Бюджет по умолчанию — 4096 обращений на сторону за матч.
- Готовность подтверждается первым ответом самой модели: `coach_session.initialized=true`, `turn_id` и `startup_reason`. До матча состояние сессии — `waiting_for_match`. Проверка связи выполняется каждые 10 секунд и возобновляет ту же сессию при обрыве процесса. `heartbeat_age_s` показывает свежесть подтверждения, `worker_health` — состояние читателя телеметрии и цикла тренера. Ошибки обработчиков пишутся как `worker_error`; циклы продолжают работу после ошибки.
- Сессии тренеров запускаются без общих стартовых хуков и внешних MCP-подключений: им достаточно сводок своей команды. Это исключает задержки посторонней инициализации перед каждым обращением.
- В `runs/team-coach-…/events.jsonl` пишутся пересмотры, продления или отмены плана, причины решений, расход и подтверждения смены режима.

Для прогона с ручным тренером есть `--mode observe`. Из `/status` берутся `session_id`, `context.clock_s` и допустимые `context.choices`. В `POST /plan` передаются `session_id`, `clock_s`, `objective`, `lane`, `bot_ids`, `ttl_s`, `reason`. **Ctrl+C** завершает сервер при запуске из своего терминала.
